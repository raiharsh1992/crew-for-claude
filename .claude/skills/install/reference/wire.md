# WIRE phase — reference

Generate config + hooks + context from the resolved manifest. **Idempotent, and
it NEVER clobbers a user-authored file.** Under `--dry-run`, print every action as
a plan and write nothing.

## The cardinal rule: never clobber user-authored content

Classify every target before writing:

- **Absent** → CREATE.
- **Present but identical to what we'd write** → SKIP (no-op).
- **Present and DIFFERENT** → this is the dangerous case. For a *mergeable*
  artifact (JSON config, `repos.config.js` repo list, settings hooks) → MERGE
  additively (add missing keys/entries, leave existing values alone). For a
  *whole-file user document* (`CLAUDE.md`, `CONTEXT.md`, an agent or command the
  user edited) → **do not overwrite**: report it and, if it still looks like an
  untouched template, offer to refresh; otherwise leave it and prompt the user.

"User-authored" includes a filled `CLAUDE.md`, an edited `.claude/agents/*`, a
hand-tuned command, and a `repos.config.js` the user maintains. When in doubt,
treat as user-authored and preserve.

## The six WIRE actions

### 1. `.claude/workflows/repos.config.js`
- Absent → CREATE from the resolved manifest, shaped per
  `repos.config.example.js` (`REPOS` array of `{name,path,class,language}` + the
  convenience views).
- Present → MERGE: add repos from the manifest not already listed (match by
  `path`); leave every existing entry exactly as the user has it. Never reorder or
  rewrite existing entries.

### 2. `.claude/skills-config.json`
- Absent → CREATE with: the issue-tracker block (reuse `bootstrap-skills`
  conventions — default `type: "local"`, `localPath: "issues/"`, default label
  vocabulary), `docs` block, `packs` flags, and the `verify` map.
- Present → MERGE additively. Specifically:
  - `verify.defaults[<language>]` — seed from each active pack's
    `verifyDefaults`, but only for stages (`verify`/`lint`/`test`) the user has
    not already set. Never overwrite a user-set command.
  - `verify.byRepo.<name>` — add an entry per resolved repo pinning
    `language`+`class`; if the user already has one, leave it.
  - `packs.<id>` — set `true` for activated packs; don't flip a user's explicit
    `false`.
  - Leave `issueTracker`/`docs` untouched if already present.

### 3. `.claude/hooks/hook-globs.env`
The env file the hook scripts source for project-specific values. Generate it so a
consumer can tune the hooks without editing the scripts:

```sh
# hook-globs.env — sourced by the .claude/hooks/* scripts for project-specific
# values. Edit these; do not edit the hook scripts. (Generated by /install;
# re-running /install preserves your edits.)

# Branch the dangerous-git hook protects against force-push / history rewrite.
PROTECTED_BRANCH="main"

# Extra pipe-separated test-only secret values to ADD to the allowlist in
# secret-patterns.sh (so your CI/fixture values don't trip the secret scan).
# Leave empty if none.
EXTRA_TEST_SECRET_ALLOWLIST=""
```

- Absent → CREATE with `PROTECTED_BRANCH` set from the detected default branch
  (read `git symbolic-ref` / the repo's HEAD; fall back to `main`).
- Present → SKIP (preserve user edits). Optionally report drift if the detected
  default branch differs from the file's value.

> Note: the hook scripts read this file if present (sourcing it is additive — the
> scripts already default `PROTECTED_BRANCH` to `main` and carry their own
> allowlist, so an absent `hook-globs.env` is harmless). Wiring the scripts to
> source it is part of the pack/hook install when present.

### 4. Activate packs
For each detected language whose pack is **active** (`python-fastapi` today):
- Copy the pack's `hooks/*` into `.claude/hooks/` (SKIP-EXISTS if already there
  and identical; report if present-and-different).
- Add each pack hook's matcher entry to `.claude/settings.json` (idempotent — add
  only if missing).
- Copy declared `commands/*.md` into `.claude/commands/` (SKIP-EXISTS).
- Set `packs.<id>: true` in `skills-config.json`.

A **spec-only** pack (java/node/go) contributes nothing here — it only yields a
GAP line in the report ("detected `<language>`, pack `<id>` spec-only — no commands
or hooks installed").

### 5. Context files (`CLAUDE.md` / `CONTEXT.md`)
- Absent → CREATE by instantiating from `templates/CLAUDE.md.template` /
  `templates/CONTEXT.md.template`.
- Present → **never overwrite**. If the file is byte-identical to the template
  (untouched), offer to refresh. Otherwise report it exists and prompt the user to
  harvest their conventions into it. The user holds the domain *why*; the installer
  must not stomp it.

### 6. `.claude/settings.json` — core hook wiring
Ensure the core matchers are present (idempotent — add only what's missing):
- `Bash` → `.claude/hooks/block-dangerous-git.sh`
- `Write|Edit|MultiEdit|NotebookEdit` → `.claude/hooks/block-secrets-in-writes.sh`
- plus any activated pack-hook matchers (e.g. `Bash` →
  `.claude/hooks/enforce-venv.sh` for python-fastapi — this wires the crew's Python venv
  rule: one `.venv` at the repo root, every Python command runs inside it. When a Python
  pack is activated this matcher is **always** added, not optional).

Preserve the user's `permissions` block and any other settings untouched.

## `--dry-run` output

Print a table of planned actions, one per target:

```
ACTION        TARGET                                  NOTE
CREATE        .claude/workflows/repos.config.js       2 repos from auto-discovery
MERGE         .claude/skills-config.json              + verify.defaults.python, + 2 byRepo
CREATE        .claude/hooks/hook-globs.env            PROTECTED_BRANCH=main
ACTIVATE-PACK python-fastapi                          + enforce-venv hook, + 8 commands
SKIP-EXISTS   CLAUDE.md                               user-authored — left untouched
GAP           node                                    pack 'node' is spec-only
```

Write **nothing** under `--dry-run`. This is the auditor's entry point — the plan
must be complete and accurate enough to review without applying it.
